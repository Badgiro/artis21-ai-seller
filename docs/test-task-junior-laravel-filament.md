# Тестовое задание: Панель управления мебельной компании с AI-продавцом

**Стек:** PHP 8.3+, **Laravel 13**, **Filament 5** (актуальные мажорные версии — более старые не принимаются), MySQL или PostgreSQL, Docker, интеграция с LLM (см. раздел 2.4).
Использовать AI-ассистенты (ChatGPT, Claude, Copilot и т.д.) при разработке — можно и нужно. Но вы должны понимать каждую строчку кода и уметь её объяснить на созвоне-защите.

---

## 1. Легенда

Мебельная фабрика продаёт кухни, шкафы, диваны и кровати. Менеджеры работают в админ-панели: ведут каталог мебели и обрабатывают заявки (лиды). Заявки приходят из чата «AI-продавец»: клиент общается с ботом, бот задаёт вопросы, и рядом с чатом в реальном времени заполняется карточка лида. Когда клиент оставил контакты — лид попадает в админку.

## 2. Что должно быть реализовано

### 2.1 Аутентификация

- Вход в панель по email + паролю (стандартный Filament login).
- Регистрация не нужна — пользователи создаются через админку и сидеры.
- Сидер создаёт админа по умолчанию: `admin@example.com` / `password`.

### 2.2 CRUD «Пользователи» (менеджеры)

Filament Resource для модели User:

| Поле | Тип | Обязательное |
|---|---|---|
| Имя | string | да |
| Email | string, уникальный | да |
| Пароль | string, хэш | да при создании, при редактировании — опционально (пустое = не менять) |

- Таблица: поиск по имени и email, сортировка, пагинация.
- Удалить самого себя нельзя (кнопка удаления скрыта или запрещена валидацией).

### 2.3 CRUD «Мебель» (каталог)

Filament Resource для модели Furniture:

| Поле | Тип | Обязательное |
|---|---|---|
| Название | string (например, «Гранада 1-28») | да |
| Тип мебели | enum: кухня, шкаф, диван, кровать (список расширяемый — PHP enum или справочник, на ваше усмотрение) | да |
| Цена | decimal, в рублях, ≥ 0 | да |
| Помещение/размер | string (например, «спальня, 200×60×240 см») | да |
| Стиль | enum или string: современный, классика, лофт, минимализм | да |

- Таблица: фильтр по типу мебели и стилю, поиск по названию, сортировка по цене.
- Сидер наполняет каталог 10–15 позициями разных типов — они нужны для рекомендаций в чате.

### 2.4 Страница «AI-продавец»

Отдельная кастомная страница внутри Filament-панели (Custom Page + Livewire). Публичный сайт делать не нужно.

Референс интерфейса — скриншот [assets/ai-seller-reference.png](assets/ai-seller-reference.png). Повторять пиксель-в-пиксель не нужно, важна структура: чат слева, живая карточка лида справа.

Макет — два блока:

```
+--------------------------------+   +----------------------+
|  Чат                           |   |  Карточка лида       |
|                                |   |                      |
|  [бот]  Здравствуйте! ...      |   |  Этап: квалификация  |
|             [клиент] шкаф      |   |  Тип мебели:  шкаф   |
|  [бот]  Какой шкаф? ...        |   |  Бюджет:      —      |
|                                |   |  Помещение:   —      |
|                                |   |  Стиль:       —      |
|  [поле ввода]     [Отправить]  |   |  Сроки:       —      |
+--------------------------------+   |  Город:       —      |
                                     |  Имя:         —      |
                                     |  Телефон:     —      |
                                     +----------------------+
```

**Логика диалога — через LLM.** Бот работает на реальной языковой модели, а не на regex/ключевых словах. Провайдер — любой доступный вам (OpenAI, Anthropic, DeepSeek, OpenRouter, GigaChat и т.п.); главное требование — проверяющий подставляет **свой** ключ в `.env`, и всё работает. Если нет возможности завести ключ для разработки — запросите тестовый у нас при старте.

Сценарий, который бот должен проводить (это цель диалога, а не жёсткий конечный автомат):

1. Приветствие: «Здравствуйте! Помогу подобрать мебель и оформить заявку. Что вас интересует — кухня, шкаф, диван, кровать?»
2. Клиент в свободной форме описывает, что хочет → LLM извлекает тип мебели, поле в карточке заполняется. Клиент может назвать несколько полей одним сообщением («нужен шкаф в спальню до 70 тысяч») — извлечь нужно все.
3. Бот уточняет недостающее: помещение/размер, стиль, бюджет. Каждый извлечённый ответ попадает в карточку.
4. После уточнений бот **рекомендует 2–3 позиции из каталога**: код делает реальный запрос в таблицу мебели по извлечённому типу (и бюджету, если указан) и передаёт найденные позиции модели — через контекст или tool calling, на ваш выбор. Модель **не должна выдумывать несуществующую мебель**.
5. Бот спрашивает сроки, город, имя, телефон — карточка дозаполняется.
6. Когда есть минимум «тип мебели + имя + телефон», бот предлагает отправить заявку. Подтверждение (или отдельная кнопка «Отправить заявку») → в БД создаётся лид → бот пишет «Заявка принята, менеджер свяжется с вами», диалог можно начать заново.

Требования к интеграции:

- Извлечение полей — структурированное: structured output / function calling / JSON mode, на ваш выбор. Парсинг ответа модели должен быть надёжным, а не «найти JSON регуляркой в тексте и надеяться».
- SDK любой: `openai-php/laravel`, Prism, официальный SDK провайдера или голый HTTP-клиент.
- Ключ и название модели — в `.env`; в `.env.example` — плейсхолдер без ключа. Ключ не хардкодить и не коммитить.
- Ошибки API (нет ключа, таймаут, 429) не роняют чат: пользователь видит вежливое сообщение, страница остаётся рабочей.
- Телефон валидируется кодом (regex/маска), а не «на доверии» модели. При невалидном — бот просит повторить.
- Системный промпт и вся логика диалога — в отдельном классе-сервисе, не внутри Livewire-компонента.
- Уводы в сторону («а расскажи анекдот») не ломают диалог — бот возвращает клиента к подбору мебели (решается системным промптом).

Требования к UI:

- Карточка справа обновляется **сразу после каждого сообщения**, без перезагрузки страницы (Livewire).
- В карточке виден текущий этап: `новый → квалификация → оформление → заявка отправлена`.
- Состояние диалога живёт в рамках сессии; после отправки заявки — сбрасывается.

### 2.5 Лиды в админке

Filament Resource «Лиды» (модель Lead), поля:

| Поле | Тип |
|---|---|
| Тип мебели | string/enum |
| Бюджет | decimal, nullable |
| Помещение/размер | string, nullable |
| Стиль | string, nullable |
| Сроки | string, nullable |
| Город | string, nullable |
| Имя | string |
| Телефон | string |
| Статус обработки | enum: новый, в работе, закрыт |
| Назначенный менеджер | FK на users, nullable |
| Дата создания | timestamp |

- Таблица: сортировка по дате (новые сверху), фильтр по статусу, поиск по имени и телефону.
- Менеджер может открыть лид, сменить статус, назначить ответственного.
- Создавать/редактировать остальные поля лида руками из админки — можно, отдельно запрещать не нужно.

## 3. Docker

Проект разворачивается **одной-двумя командами** на чистой машине с Docker:

```bash
docker compose up -d
docker compose exec app php artisan migrate --seed
```

(допустимо свернуть в Makefile или entrypoint — тогда опишите в README).

- Минимум сервисов: `app` (php-fpm), `nginx`, `db` (MySQL/PostgreSQL). Laravel Sail использовать можно.
- Порты и креды БД — через `.env`; в репозитории лежит готовый `.env.example`, который работает без правок.
- После запуска панель доступна на `http://localhost:<порт>`, порт указан в README.

## 5. Критерии приёмки (чек-лист)

- [ ] `docker compose up` + миграции с сидами → рабочая панель, вход под админом из сидера.
- [ ] CRUD пользователей работает, пароль хэшируется, себя удалить нельзя.
- [ ] CRUD мебели работает, фильтры по типу и стилю работают, сиды каталога на месте.
- [ ] Проект на актуальных мажорных версиях: Laravel 13 + Filament 5.
- [ ] Чат проводит по сценарию: тип мебели → уточнения → рекомендации **из реального каталога** → контакты → заявка.
- [ ] Поля извлекаются LLM из свободного текста, в том числе несколько полей из одного сообщения.
- [ ] Проверяющий подставляет свой API-ключ в `.env` — и чат работает без правок кода.
- [ ] При отсутствии ключа или ошибке API чат не падает, показывает понятное сообщение.
- [ ] Карточка лида обновляется по ходу диалога без перезагрузки страницы.
- [ ] После отправки заявки лид появляется в разделе «Лиды» со всеми заполненными полями.
- [ ] Невалидный телефон не проходит; увод разговора в сторону не ломает бота.
- [ ] README актуален: по нему проект запускается с нуля.

## 6. Что оцениваем

1. **Работает ли сценарий целиком** — от `docker compose up` до лида в админке. Это главное.
2. Качество кода: структура (тонкие контроллеры/страницы, логика диалога вынесена в отдельный класс-сервис, а не размазана по Livewire-компоненту), именование, миграции, валидация.
3. Владение Filament: используются его штатные механизмы (Resources, формы, фильтры), а не самописные велосипеды рядом.
4. Качество LLM-интеграции: осмысленный системный промпт, структурированное извлечение полей, обработка ошибок API, рекомендации строго из каталога.
5. Аккуратность мелочей: enum'ы вместо магических строк, сиды, `.env.example`, README.
6. На защите — способность объяснить любой фрагмент кода и обосновать решения. «Так сгенерила нейронка» без понимания = провал.

Красивый пиксель-перфект UI **не оцениваем** — стандартного вида Filament и простой вёрстки чата достаточно.

## 7. Бонусы (не обязательно, плюс к оценке)

- Стриминг ответов бота (эффект «печатает» через streamed response).
- Tool calling: модель сама вызывает поиск по каталогу как инструмент, а не получает позиции в контексте.
- Уведомление о новом лиде (Filament notification / email в log-драйвер).
- Feature-тесты: создание лида из диалога (LLM замокан), валидация телефона.
- Быстрые кнопки-подсказки в чате («нужна кухня», «диван до 70т»).
